## 1. 命名规范（Java 专属）

### 1.1 包名

- 根包 `com.knowly`，子包按模块：`com.knowly.{module}.{layer}`
- 全小写，不用下划线，不缩写模块名
- 示例：`com.knowly.core.pipeline`、`com.knowly.embed.sink.pgvector`

### 1.2 类名

- UpperCamelCase
- **接口不加 `I` 前缀**：用 `ChunkSink` 不用 `IChunkSink`
- **SPI 实现用 `{技术}{角色}`**：`PgVectorSink`、`DashScopeEmbeddingProvider`、`TesseractOcrEngine`
- 工具类用 `Utils` 后缀：`HashUtils`、`PathSanitizer`
- 异常用 `Exception` 后缀：`ConfigException`、`ParseException`
- 测试类用 `被测类名 + Test`：`HashUtilsTest`

### 1.3 方法/变量

- camelCase，见名知义，不缩写（用 `document` 不用 `doc`，除领域通用缩写 ID/URL/HTTP）
- 布尔值用 `is`/`has`/`should`/`can` 前缀：`isEnabled`、`hasContent`
- 常量 UPPER_SNAKE_CASE：`SUPPORTED_EXTENSIONS`、`DEFAULT_QPS_LIMIT`
- 避免否定布尔：用 `isEnabled` 不用 `isNotDisabled`

### 1.4 枚举

- 单数名（`BlockType` 不用 `BlockTypes`）
- 成员 UPPER_SNAKE_CASE
- 带描述字段便于日志/UI 展示

## 2. 代码风格

| 项 | 规则 |
|---|---|
| 缩进 | 4 空格，禁 Tab |
| 行宽 | 120 字符 |
| 花括号 | K&R 风格（`{` 不换行） |

**强制工具**：Spotless（格式化）+ Checkstyle（风格检查）。提交前必须通过。

## 3. 异常处理与错误码

### 3.1 异常体系

```
RuntimeException
  └─ KnowlyException（所有知了异常的基类）
       ├─ ConfigException     配置错误
       ├─ ParseException      摄取解析错误
       ├─ CleanException      清洗错误
       ├─ EmbedException      向量化错误
       └─ SinkException       产出写入错误
```

- **一律非受检**（extends RuntimeException）：知了是流水线工具，异常统一在 PipelineEngine 边界捕获，不强迫业务代码层层声明 throws
- 异常必须含上下文：错误码 + 用户可读消息 + 技术细节（detail）

### 3.2 错误码规范

格式：`{阶段}_{序号}`，已在 `ErrorCode` 常量类登记。**已发布的错误码不可变更**（是公开契约）。

| 阶段前缀 | 示例 | 含义 |
|---|---|---|
| `CONFIG_xxx` | CONFIG_001 | 配置文件格式/必填/依赖/值非法 |
| `PARSE_xxx` | PARSE_001 | 文档解析失败 |
| `CLEAN_xxx` / `CHUNK_xxx` | CHUNK_001 | 清洗/分段失败 |
| `EMBED_xxx` | EMBED_001 | Embedding API 调用失败 |
| `SINK_xxx` | SINK_001 | 向量库写入失败 |
| `SEC_xxx` | SEC_003 | 路径穿越/认证失败 |
| `JOB_xxx` | JOB_001 | 任务互斥/状态冲突 |

新增错误码必须先在 `ErrorCode` 登记，再在代码引用常量（禁止字面量）。

### 3.3 异常使用原则

- **抛出**：用 `new XxxException(errorCode, message, detail, cause)`，message 面向用户，detail 面向开发者
- **捕获**：只在能处理的层级捕获。PipelineEngine 捕获单文件异常记入 ErrorCollector 后继续（失败隔离）；不可恢复错误（如配置错）向上传播
- **禁止**：`catch (Exception e) { }` 空吞；`throw new RuntimeException(e)` 丢失上下文

## 4. 日志规范

### 4.1 框架与格式

- 接口：SLF4J（`org.slf4j.Logger`）
- 实现：Logback，结构化 JSON（含 timestamp/level/traceId/documentId/stage）
- 变量占位符：用 `{}` 不用字符串拼接（`log.info("处理文件: {}", path)` 不用 `log.info("处理文件: " + path)`）

### 4.2 级别使用

| 级别 | 用途 |
|---|---|
| ERROR | 系统级故障，需要人工介入（如数据库连不上） |
| WARN | 可恢复的异常（单文件解析失败，已跳过） |
| INFO | 关键业务节点（流水线启动/完成、任务状态变更） |
| DEBUG | 详细诊断信息（chunk 分段细节、阶段进度） |
| TRACE | 极细粒度（单个 token 处理）—— 生产不开 |

### 4.3 必含字段

业务日志尽量带 `jobId`/`documentId`/`filePath`，便于追踪。示例：
```java
log.info("流水线启动: jobId={}, files={}", jobId, total);
log.warn("文件处理失败: {}, error={}", file, e.getMessage());
```

### 4.4 密钥脱敏（铁律）

**任何日志/报告/异常信息中不得出现明文密钥。** 打印配置、错误细节前必须过 `SecretMasker.mask()`：

```java
// 错误：可能泄露 API key
log.error("配置加载失败: {}", config);

// 正确：先脱敏
log.error("配置加载失败: {}", SecretMasker.mask(config.toString()));
```

## 5. 编码实践

### 5.1 设计模式（恰当应用，不过度）

| 模式 | 用在哪 | 原则 |
|---|---|---|
| 工厂+注册表 | 组件实例化（SinkRegistry/ChunkingRegistry） | 避免 switch-case，加新组件不改核心 |
| 观察者 | PipelineEvent 进度通知 | 内核不依赖 CLI/Web |
| 责任链 | DefaultTextCleaner 清洗步骤 | 每步可独立测试，顺序可配 |
| 策略 | ChunkingStrategy/DedupStrategy | 多算法可切换 |
| 建造者 | PipelineEngine.Builder/RetryTemplate.Builder | 多参数构造可读 |
| 模板方法 | 仅当骨架固定、步骤可变时 | 能用简单方案不引入 |

**判断标准**：能用简单 if/for 解决的，不引入模式。引入模式必须在代码注释或 ADR 说明理由。

### 5.2 枚举

- 单数名，UPPER_SNAKE_CASE 成员
- 带描述字段：`BlockType("表格")` 便于日志/UI

### 5.3 常量管理

- 魔法数字必须提取为常量：`private static final int DEFAULT_QPS_LIMIT = 10;`
- 常量集中放类顶部，`static final`
- 配置默认值放 `knowly-defaults.yaml`，不放代码

### 5.4 不可变优先

- 数据模型用 `record`（RawDocument/TextChunk/EmbeddedChunk）
- record 天然不可变、并发安全、equals/hashCode 自动生成
- 集合返回不可变视图：`List.copyOf()` / `Collections.unmodifiableList()`

## 6. 依赖管理

### 6.1 版本统一

- 父 POM `dependencyManagement` 统一声明所有版本
- 子模块引用时不写 version（继承父管理）
- 版本升级改一处，全局生效

### 6.2 scope 规范

| scope | 用途 |
|---|---|
| compile（默认） | 运行时需要的依赖 |
| provided | 编译需要、运行时容器提供（如 servlet API） |
| test | 仅测试需要（JUnit/AssertJ） |

### 6.3 依赖原则

- 内核纯净：`knowly-core` 不依赖任何 Web 框架（无 Spring MVC）、不依赖实现模块（ingest/clean/embed）
- 实现模块依赖 core 接口，**模块之间不直接依赖**
- 重依赖（OCR/ASR）可选：core 不能强依赖 tess4j
- 冲突排查：`mvn dependency:tree`，用 `<exclusions>` 排除传递冲突

## 7. 配置项管理

### 7.1 配置键命名

- YAML 键：snake_case（`max_size`、`qps_limit`、`traditional_to_simplified`）
- 环境变量：UPPER_SNAKE，`KNOWLY_` 前缀或业务名（`DASHSCOPE_API_KEY`、`PG_PASSWORD`）

### 7.2 配置层级

```
全局默认 (classpath:knowly-defaults.yaml)
   ↓ 覆盖
项目配置 (--config pipeline.yaml)
   ↓ 覆盖
命令行参数 (--input / Web 请求)
```

由 `ConfigLoader` 三层合并。**业务代码禁止硬编码参数**，一律从 `PipelineConfig` 读取。

### 7.3 环境变量解析

- 占位符：`${VAR}` 或 `${VAR:default}`
- 优先级：环境变量 > app_config 表 > 默认值
- 解析在 `ConfigLoader.resolveEnvVars()` 统一做
- **密钥永不硬编码**：用 `${PG_PASSWORD}` 占位，由环境变量注入

### 7.4 校验

启动时校验（`ConfigLoader.validate()`）：
- 必填项缺失 → 明确报"哪个字段、期望什么"
- 依赖关系（向量库 sink 但无 API key）→ 报错
- 值范围（max_size > 0；overlap ∈ [0, maxSize)）→ 报错

## 8. 安全编码（后端专属）

### 8.1 SQL 参数化（铁律）

所有数据库操作用 `PreparedStatement`，禁止字符串拼接 SQL：

```java
// 正确
PreparedStatement ps = conn.prepareStatement("SELECT * FROM chunks WHERE id = ?");
ps.setString(1, chunkId);

// 错误（SQL 注入）
String sql = "SELECT * FROM chunks WHERE id = '" + chunkId + "'";
```

### 8.2 路径穿越防护

用户输入的文件/目录路径，必须过 `PathSanitizer`：

```java
Path safe = PathSanitizer.sanitize(userInput, allowedBaseDir);
```

Web 控制器的所有路径参数必须 normalize 后再用。

### 8.3 YAML 安全

用 `SafeConstructor`（禁任意类反序列化）：

```java
Yaml yaml = new Yaml(new SafeConstructor(new LoaderOptions()));
```

### 8.4 密钥三不铁律

- **不进代码**：API key/密码用环境变量
- **不进日志**：打印前过 `SecretMasker.mask()`
- **不进异常/报告**：error-report.json 不得含明文密钥

### 8.5 反序列化白名单

JSONL 回灌（reembed）从外部数据读回时，校验字段类型，拒绝非预期结构。

## 9. 并发编码

### 9.1 基本规则

- 用 `java.util.concurrent`（ExecutorService/CompletableFuture/并发集合），**禁裸 `new Thread()`**
- 共享状态最小化；必须共享时用并发结构或 `synchronized` 保护
- 线程命名：`ThreadFactory` 设置有意义的名（`knowly-ingest-worker`），便于诊断

### 9.2 流水线并发模型

PipelineEngine 采用"有界队列 + 多阶段线程池 + 背压"：

- 每阶段独立线程池，线程数可配（`concurrency.ingest_threads` 等）
- 阶段间 `ArrayBlockingQueue`，队列满阻塞上游 = 背压
- `ThreadPoolExecutor` 拒绝策略用 `CallerRunsPolicy`（队列满时调用方执行，自然降速）
- embedding 调用受 `RateLimiter`（令牌桶）限流

### 9.3 状态保护

- 任务互斥用 `AtomicBoolean.compareAndSet`（无竞态占用），不用 volatile 的 check-then-action
- 事件监听器列表用 `CopyOnWriteArrayList`（读多写少）
- shutdown 信号用 `volatile boolean`（保证跨线程可见）

### 9.4 优雅停机

- `PipelineEngine` 实现 `AutoCloseable`
- `cancel()` 设置停机标志，循环开头检查
- 线程池 `shutdown()` + `awaitTermination(30s)` + `shutdownNow()` 兜底
- CLI 注册 `Runtime.getRuntime().addShutdownHook()`

## 10. API/SPI 设计规范

### 10.1 参数对象化

参数超过 3 个，用对象封装（record 或 Builder），避免构造函数参数爆炸：

```java
// 好
PipelineEngine.builder().parser(p).cleaner(c).build();

// 差
new PipelineEngine(p, c, d, e, f, g, h);  // 谁记得住第 5 个是啥
```

### 10.2 返回值

- 返回集合时用不可变（`List.copyOf`），不返回 null 集合
- 查询可能无结果用 `Optional<T>`
- SPI 接口返回 `StageResult<O>`（成功产出 或 跳过），不抛异常给调用方决策

### 10.3 异常契约

- SPI 接口在 Javadoc 声明"抛什么异常、什么含义"
- 接口实现抛出的异常必须是 `KnowlyException` 子类（统一体系）
- 可恢复异常（如单文件失败）由 PipelineEngine 捕获记 ErrorCollector

### 10.4 版本兼容（前向兼容）

- record 加字段不破坏老消费方（JSONL metadata 可扩展）
- 配置 schema 加字段不破坏老配置（缺失字段走默认值）
- 错误码已发布不可变更
- SPI 接口加方法用 `default` 提供默认实现

## 11. 性能编码

### 11.1 大文件处理

- 流式读取，不全量加载：PDF/Word 用 Tika 的 stream API
- GB 级文件不 OOM：单文件内存恒定（per-document 流式处理）
- `Files.walk()` 用 try-with-resources 保证流关闭

### 11.2 循环内不创建对象

```java
// 差：每次循环创建 Pattern
for (String line : lines) {
    Pattern p = Pattern.compile("^\\d+");  // 编译开销大
    ...
}

// 好：提取为 static final 常量
private static final Pattern NUMERIC_START = Pattern.compile("^\\d+");
```

### 11.3 批量优先

- embedding 调用：累积到 batch_size 批量调 API（省请求开销）
- 向量库写入：批量 upsert（PgVector 用 batch insert）
- 文件扫描：`Files.walk()` 一次遍历，不在循环里逐个 `exists()` 检查

### 11.4 字符串拼接

- 循环内：`StringBuilder`
- 日志：`{}` 占位符（SLF4J 会优化）
- 单次：`+` 即可（编译器优化）

## 12. 测试规范（后端专属）

### 12.1 框架

- JUnit 5 + AssertJ
- 断言库：AssertJ（`assertThat`），不用 JUnit 的 `assertEquals`（AssertJ 链式更可读）

### 12.2 命名与结构

- 测试类：`被测类名 + Test`（`HashUtilsTest`）
- 测试方法：`should_xxx_when_xxx`（`should_dedup_when_content_hash_same`）
- 结构：AAA 模式（Arrange / Act / Assert），用空行或注释分隔

### 12.3 边界必测

每个功能必测的边界：空输入、超大输入、损坏输入、null、纯标点/空白。

### 12.4 覆盖率要求

| 模块 | 行覆盖率 |
|---|---|
| knowly-common（工具类） | ≥ 90% |
| knowly-core（内核/配置） | ≥ 80% |
| knowly-clean（清洗/分段） | ≥ 80% |
| knowly-ingest（解析/OCR） | ≥ 60% |
| knowly-embed（向量化/Sink） | ≥ 60% |
| knowly-api / knowly-cli | ≥ 50% |

### 12.5 mock 与集成测试

- 外部依赖（embedding API/向量库）用 mock 或 Testcontainers
- mock embedding：实现 `EmbeddingProvider` 返回固定向量，不消耗 API 额度
- 端到端集成测试用 `generate_samples.py` 生成的样例文档

### 12.6 测试独立

- 不依赖执行顺序
- 不依赖外部状态（用 `@TempDir` 隔离文件）
- 一个测试一个断言重点（失败时定位清晰）
- 不为覆盖率凑数（测有意义的行为）
