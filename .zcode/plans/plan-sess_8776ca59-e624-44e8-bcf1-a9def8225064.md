# v0.2 图谱层实现方案

## 概览

5 个部分，从底层到上层依次实现：

### 1. 创建 knowly-graph 模块 + 依赖
- 创建 `knowly-graph/pom.xml`，依赖 knowly-core + dashscope-sdk + neo4j-java-driver
- 注册到父 POM（取消注释 + 加 dependencyManagement）
- 包结构：`com.knowly.graph.llm` / `com.knowly.graph.extractor` / `com.knowly.graph.store`

### 2. DashScopeLlmProvider（LLM 调用）
- `DashScopeLlmProvider implements LlmProvider`
- 用 DashScope SDK 的 `Generation.call(GenerationParam)` 调 qwen-max
- 内部拼 system prompt + user prompt（system 放抽取规则）
- 支持 `responseFormat=json_object`（强制 JSON 输出）
- 复用 RateLimiter + RetryTemplate

### 3. LlmEntityExtractor + LlmRelationExtractor
- **LlmEntityExtractor**：遍历每个 TextChunk，发 LLM prompt 抽取实体（类型可配：方剂/穴位/概念/人物...），解析 JSON 返回 `List<Entity>`
- **LlmRelationExtractor**：基于已抽取实体列表，发 LLM prompt 抽取关系（关系类型可配：组成/主治/相关...），解析 JSON 返回 `List<Relation>`
- **实体消歧**（F4.3）：规范化（TextNormalizer.normalize）→ 相同 normalizedKey 合并别名

### 4. Neo4jGraphStore
- `Neo4jGraphStore implements GraphStore`
- 用 Neo4j Java Driver 写入节点（Entity）和边（Relation）
- Cypher 语句：`MERGE` 实体节点 + `MERGE` 关系边（幂等）
- 配置：`bolt://localhost:7687`，用户 `neo4j`，密码 `knowly_dev`

### 5. PipelineEngine 接入 + CLI/API 装配
- **PipelineEngine**：Builder 加 4 个可选注入点（entityExtractor/relationExtractor/graphStore/llmProvider）；在 doSink 之前加 doGraph 阶段
- **doGraph**：对每个文档的 TextChunk 列表做实体抽取 → 关系抽取 → 写入 GraphStore
- **PipelineEvent**：加 GraphStarted/GraphCompleted 事件
- **RunCommand + JobService**：装配图谱组件（有 API Key + 有图谱配置时才启用）
- **前端**：清洗参数加"启用图谱"复选框

### 需要你做的
- Docker 部署 Neo4j：`docker run -d --name knowly-neo4j -p 7687:7687 -p 7474:7474 -e NEO4J_AUTH=neo4j/knowly_dev neo4j:5`
- 确认 LLM 模型选择：qwen-max（效果最好、最贵）vs qwen-plus（性价比）vs qwen-turbo（最便宜）

### 费用预估
- 假设 320 个 chunk，每 chunk 发 1 次 LLM 调用（实体+关系合并到一个 prompt）
- qwen-plus：约 0.004 元/千 token，每 prompt 约 1000 token（prompt + 响应）
- 320 × 0.004 ≈ **1.3 元**
- 整个倪师著作（5 本书约 1500 chunk）：约 **6 元**
