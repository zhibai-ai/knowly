## 待编写章节结构

1. **部署架构**：knowly-api（Spring Boot 服务）+ knowly-web（nginx 静态资源）+ 依赖（PostgreSQL/Tesseract）的拓扑
2. **打包**：knowly-api 打可执行 jar / war；knowly-web `npm run build` 产静态资源
3. **Docker 部署**：
   - knowly-api 的 Dockerfile（基于 jdk17 镜像）
   - knowly-web 的 Dockerfile（基于 nginx 镜像）
   - docker-compose.yml（含 PostgreSQL+PgVector、knowly-api、knowly-web 一体化）
4. **依赖服务部署**：
   - PostgreSQL + PgVector 扩展（生产配置：连接池、内存、HNSW 参数）
   - Tesseract + 中文字体（生产环境安装）
5. **配置外部化（12-factor）**：
   - 环境变量清单（`DASHSCOPE_API_KEY` / `PG_USER` / `PG_PASSWORD` / `KNOWLY_*`）
   - application.yml 的生产配置（日志路径、数据目录、线程池大小）
   - 敏感信息只走环境变量，不进镜像
6. **启动与停止**：
   - knowly-api 启动命令（`java -jar` + JVM 参数）
   - knowly-web nginx 配置（反向代理 API）
   - 优雅停机（SIGTERM 触发）
7. **健康检查**：knowly-api 的 `/actuator/health` 端点；依赖服务连通性检查
8. **升级与回滚**：版本升级流程；schema migration（PgVector 表结构变更）；回滚策略
9. **监控**（衔接运维手册）：日志聚合接入；指标暴露（Prometheus 端点）；告警阈值
