## 1. 测试策略

### 1.1 三层测试

| 层 | 范围 | 工具 | 运行方式 |
|---|---|---|---|
| 单元测试 | 各模块独立测（清洗/分段/去重/工具类） | JUnit 5 + AssertJ | `mvn test` |
| 集成测试 | 端到端流水线（摄取→清洗→产出） | JUnit 5 + 测试样例 | `mvn verify` |
| 手动验收 | 对照验收标准 A1-A19 | 人工 | Web UI / CLI 操作 |

### 1.2 测试环境

| 依赖 | 用途 | 方式 |
|---|---|---|
| 测试样例文档 | 验证各种格式解析 | `knowly-dist/examples/samples/generate_samples.py` 生成 |
| mock embedding | 不消耗 API 额度的向量测试 | mock EmbeddingProvider |
| Testcontainers（计划） | 自动化集成测试 | v0.2 补充 |

> - ✅ 已验证：有自动化测试或已手动跑通

> - ⏳ 待验证：代码就绪，需用样例手动验收

## 4. 覆盖率要求

| 模块 | 行覆盖率要求 | 优先级 |
|---|---|---|
| knowly-common（工具类） | ≥ 90% | 高 |
| knowly-core（内核引擎） | ≥ 80% | 高 |
| knowly-clean（清洗/分段） | ≥ 80% | 高 |
| knowly-ingest（解析/OCR） | ≥ 60% | 中 |
| knowly-embed（向量化/Sink） | ≥ 60% | 中 |
| knowly-api（Web 控制器） | ≥ 50% | 低（依赖集成测试） |
| knowly-cli（CLI 命令） | ≥ 50% | 低 |

> v0.1 以手动验收为主，单元测试在 v0.2 补充。

## 5. 测试命名与组织规范

### 5.1 命名

```java
// 测试类：被测类名 + Test
class StructureAwareChunkingTest {
    // 测试方法：should_xxx_when_xxx
    @Test
    void should_dedup_when_content_hash_same() { ... }
}
```

### 5.2 结构（AAA 模式）

```java
@Test
void should_split_large_text_at_sentence_boundary() {
    // Arrange
    String text = "第一句。第二句。第三句。";
    
    // Act
    List<TextChunk> chunks = chunking.chunk(doc);
    
    // Assert
    assertThat(chunks).isNotEmpty();
    assertThat(chunks.get(0).text()).doesNotContain("。第二句。");
}
```

### 5.3 边界必测

每个功能必须测的边界场景：
- 空输入
- 超大输入（> maxSize）
- 损坏输入（corrupted PDF）
- null / 空字符串
- 纯标点/纯空白
